### Syncing from upstream

Check the gap before assuming the fork is current:

```sh
git fetch upstream
git rev-list --left-right --count origin/develop...upstream/develop   # ahead<TAB>behind
```

The fork carries no commits of its own on `develop`, so syncing is normally a
fast-forward. Never rewrite `develop`'s history:

```sh
git checkout develop
git merge --ff-only upstream/develop
```

If `--ff-only` fails, stop and report it — that means `develop` has diverged
and needs a decision, not a force-push.

## Keeping this file out of upstream

This file is committed to the fork so it survives re-clones, which means a
branch cut from fork `develop` will carry it into any upstream PR diff. Two
rules prevent that:

1. **Base upstream-bound branches on `upstream/develop`, not fork `develop`:**
   ```sh
   git fetch upstream
   git checkout -b my-feature upstream/develop
   ```
   Such a branch has no `CLAUDE.md` in its history, so it can never leak.
2. **Check before opening or pushing to an upstream PR:**
   ```sh
   git diff --name-only upstream/develop...HEAD | grep -x 'CLAUDE.md' \
     && echo "STOP: CLAUDE.md would go upstream"
   ```
   If it is there, remove it from the branch (`git rm CLAUDE.md` in a cleanup
   commit, or rebase it out) before the PR goes up.

Never propose adding this file, or any variant of it, to `boostorg/website-v2`.

## Project basics

Django 5.2 + Tailwind, run through Docker Compose, with `just` as the task
runner and `pytest` for tests.

```sh
docker compose up                        # bring up the stack
just migrate                             # apply migrations
just makemigrations                      # create migrations
just manage <cmd>                        # any manage.py command
just test                                # full test suite
docker compose run --rm web pytest       # pytest directly (targeted runs)
```

- Test config lives in `pytest.ini` (`config.test_settings`, `--reuse-db
  --no-migrations`). Test files are `test_*.py`.
- Tests marked `asciidoctor` need local asciidoctor rendering.
- Frontend CSS is built with Tailwind: `npm run dev` to watch, `npm run build`
  for production. There are separate configs for docs
  (`docstailwind.config.js`) and the user guide (`userguidetailwind.config.js`).

### Style checks

`pre-commit` is the source of truth — Black, Ruff, djhtml, django-upgrade, plus
whitespace and YAML checks. Run the relevant hook rather than reformatting by
hand:

```sh
pre-commit run --all-files
pre-commit run black
pre-commit run ruff
pre-commit run djhtml
```

Match the surrounding code's conventions; this is an upstream-tracking fork, so
keep diffs minimal and avoid drive-by reformatting that would complicate future
merges.
